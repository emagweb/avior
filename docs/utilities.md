# Utilities

Every class generated by `inc/_helpers.sass`, `inc/_grid.sass` and `components/_colors.sass`.

Class names follow the Emmet dictionary: first letters of the property, then first letters
of the value. The numeric part is the value itself, taken from the design.

## Generated ranges

Every family is generated with a step, and both the step and the limit are variables.
The defaults below come from `inc/_variables.sass`.

| class                           | range   | step | produces                                     | note                                            |
| ------------------------------- | ------- | ---- | -------------------------------------------- | ----------------------------------------------- |
| `w-N`                           | 0–100   | 5    | `width`, `min-width`, `max-width` in `%`     | also sets `display: block`                      |
| `h-N`                           | 0–100   | 5    | `height`, `min-height`, `max-height` in `vh` | also sets `display: block`                      |
| `w-p-N`                         | 0–800   | 4    | the same three in `px`                       |                                                 |
| `h-p-N`                         | 0–800   | 4    | the same three in `px`                       |                                                 |
| `p-l-N` `p-r-N` `p-t-N` `p-b-N` | 0–160   | 4    | `padding` on one side, `px`                  |                                                 |
| `p-x-N` `p-y-N`                 | 0–160   | 4    | `padding` on two sides, `px`                 |                                                 |
| `m-l-N` `m-r-N` `m-t-N` `m-b-N` | 0–160   | 4    | `margin` on one side, `px`                   |                                                 |
| `m-x-N` `m-y-N`                 | 0–160   | 4    | `margin` on two sides, `px`                  |                                                 |
| `s-N`                           | 0–160   | 4    | vertical spacer `N` px tall                  | `clear: both`, halves below `sm`                |
| `fz-N`                          | 0–72    | 1    | `font-size` in `px`                          |                                                 |
| `fw-N`                          | 100–900 | 100  | `font-weight`                                |                                                 |
| `lh-N`                          | 100–500 | 5    | `line-height` as `N × 0.001`                 | `lh-150` is `1.5`; sets `display: inline-block` |
| `bw-N`                          | 0–24    | 1    | `border-width` in `px`                       |                                                 |
| `r-N`                           | 0–60    | 4    | `border-radius` in `px`                      |                                                 |

Border width and font size keep a step of 1, because `bw-2` and `fz-13` are ordinary
values. Font weight only ever moves in hundreds.

## Grid

Plain CSS Grid, twelve columns by default. No wrapper row, no negative margins.

| class                             | CSS                                           |
| --------------------------------- | --------------------------------------------- |
| `grid`                            | `display: grid` with `$columns` equal columns |
| `cols-1` … `cols-12`              | `display: grid` with N equal columns          |
| `col-1` … `col-12`                | `grid-column: span N` for a child             |
| `cols-auto-100` … `cols-auto-400` | `repeat(auto-fit, minmax(Npx, 1fr))`, step 20 |
| `g-N`                             | `gap`, 0–160 step 4                           |
| `gcg-N`                           | `column-gap`                                  |
| `grg-N`                           | `row-gap`                                     |

```jsx
<div className="cols-3 g-40">
  <div>…</div>
</div>

<div className="grid g-24">
  <div className="col-8">…</div>
  <div className="col-4">…</div>
</div>
```

Below the `sm` breakpoint `grid`, `cols-*` and `col-*` collapse to a single column.
`cols-auto-*` needs no breakpoint at all: it reflows on its own as soon as a column
would drop under the given minimum.

## Titles

A heading takes one class from this family and nothing else. Alignment, width and any
extra spacing belong to the element around it, so retuning a heading never means editing
markup. Sizes are `rem` against a 16px root, and every class leaves the same 24px below
itself: a heading and the text under it read as one block, at any size.

| class             | size | weight | line-height | gap  | role                                 |
| ----------------- | ---- | ------ | ----------- | ---- | ------------------------------------ |
| `title-intro`     | 64px | 700    | 1.05        | 24px | the hero `h1`, one per site          |
| `title-intro-sub` | 40px | 600    | 1.2         | 24px | the line that follows the hero `h1`  |
| `title-page`      | 48px | 500    | 1.1         | 24px | `h1` of an inner page, set by `Page` |
| `title-section`   | 48px | 600    | 1.2         | 24px | section heading                      |
| `title`           | 24px | 500    | 1.35        | 24px | section heading inside a text page   |
| `title-sub`       | 20px | 500    | 1.4         | 24px | subheading inside a text block       |
| `title-card`      | 18px | 600    | 1.4         | 24px | card or list item heading            |
| `title-mini`      | 16px | 600    | 1.5         | 24px | label at body size                   |

The two `intro` classes belong to the hero and nowhere else. Further down a page the
largest heading is `title-section`.

The four large sizes step down twice, so a heading never fills a phone screen:

```
title-intro        64 → 44 → 36
title-page         48 → 36 → 32
title-intro-sub    40 → 32 → 28
title-section      48 → 40 → 32
                        sm    xs
```

No title class sets a font. The face comes from `body`, so changing `$basic` changes every
heading with it. A second face is applied where it is needed with `ff-intro`.

## Responsive helpers

These carry the breakpoint inside the class, so one class replaces two.

| class      | behaviour                                            |
| ---------- | ---------------------------------------------------- |
| `m-show`   | hidden by default, shown below `sm`                  |
| `m-hide`   | shown by default, hidden below `sm`                  |
| `m-block`  | `display: block` below `sm`, plus 24px bottom margin |
| `m-center` | centred text and box below `sm`                      |
| `wide`     | `min-width: 90%` and centred below `sm`              |

Note the overloaded `m-` prefix: `m-b-24` is a margin, `m-block` is mobile behaviour.

## Colours

Three families are generated from `$palette` in `_variables.sass`:

| class     | CSS                                       |
| --------- | ----------------------------------------- |
| `c-NAME`  | `color`                                   |
| `bg-NAME` | `background-color`                        |
| `bc-NAME` | `border-color` plus `border-style: solid` |

Names in the default palette: `dark`, `grey`, `medium`, `light`, `blue`, `pink`, `yellow`,
`violet`, `orange`, `red`, `green`, `white`, `theme`, `accent`.

`theme` and `accent` are aliases of other palette entries, meant to be repointed per
project. Use them in components so a project can be recoloured without touching markup.

A second list sits next to the palette:

```sass
$light-colors: ("grey", "light", "white")
```

These are the colours a white label cannot sit on. A solid button in one of them gets dark
text, and so does an outline button on hover, once its background is filled.

An outline button at rest keeps the button colour as its label. Light outline buttons are
built for dark sections, where a white border with a white label is what you want.

Add the name of any new light colour to this list, otherwise its solid button keeps a white
label on a light background. Aliases are covered automatically: if `theme` points at one of
these colours, it is treated as light too.

| class    | CSS                                                     |
| -------- | ------------------------------------------------------- |
| `dashed` | `border-style: dashed`, overrides the solid from `bc-*` |
| `double` | `border-style: double`, overrides the solid from `bc-*` |
| `b-none` | `border: none`                                          |
| `bg-tr`  | `background-color: transparent`                         |

## Why `!important`

Most utilities carry `!important`. A utility is a single class and loses to any component
rule, which is a descendant selector: `.page section p` beats `.fz-32` on specificity no
matter which loads later. `!important` is what lifts the utility above it. Component
styles never compete with utilities and stay clean. See [decisions.md](decisions.md).

`dashed` and `double` are deliberately without `!important`: they are declared after the
`bc-*` block in the same file, and with equal specificity the later rule wins.
